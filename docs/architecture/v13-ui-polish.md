## 4. 移动端专项修复（重点）

### 4.1 日期键盘盖住
- **所有** `el-date-picker` 加 `editable="false"`：禁止原生键盘弹出，只走面板
- 移动端全部 `input` 字号 ≥16px（防 iOS 自动缩放页面）：`@media (max-width:768px){ .el-input__inner{font-size:16px} }`
- 下单时间 datetime 面板移动端宽度适配（沿用 V4 堆叠方案，时间列可滚动）

### 4.2 跨月日期选择（根因：V4 竖排双月面板太高，第二个月在屏幕外）
方案：**移动端弃用 daterange 弹层，改用两个独立日期面板**（桌面端不变）：

- **酒店订单新建/编辑表单**：
  - 桌面：`type=daterange`（现状）
  - 移动：`class="mobile-only"` 的「入住日期」「离店日期」两个 `type=date` 输入框，
    分别绑定 `form.dateRange[0]` / `form.dateRange[1]`；
    初始化 `form.dateRange = ['', '']`（避免 null 索引绑定报错）；
    离店 `:disabled-date="d => form.dateRange[0] && d < new Date(form.dateRange[0])"`（不早于入住）；
    入住变更时若晚于离店则自动同步离店 = 入住 + 1 天
  - 「共 N 晚」提示两个端共用 `formNights` 计算（现有逻辑）
- **酒店订单筛选栏** / **高尔夫订单筛选栏**（移动端 filter-extra 区）：
  - 桌面 daterange 不变；移动端两个独立 date 输入（起/止），同样 disabled-date 互锁
- 高尔夫下单表单仅单个打球日期，只需 4.1 修复，无跨月问题

### 4.3 其他移动体验
- 抽屉/弹窗底部操作区（取消/保存）`position:sticky; bottom:0` 白底上分隔线，长表单滚动时按钮始终可见
- 移动列表卡片圆角 10px、间距 10px；操作按钮高度统一 ≥40px
- `el-input-number` 步进按钮触控区加大（32px 高）

## 5. 边界约束

- **不改**：业务逻辑、API、数据模型、路由、状态机、导出、拼音搜索、红色利润体系

- 不引第三方 UI 库/CSS 框架（UnoCSS 等不引入，纯 CSS 变量 + Element Plus 主题）
- 所有改动集中在 web/src；后端零改动
