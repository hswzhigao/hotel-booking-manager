# V4 设计 — iPhone/移动端适配

状态：**Finalized**（2026-09-21）

## 目标
375px 宽度（iPhone SE/标准）下全功能可用；桌面端（≥768px）保持现有布局不变。

## 方案：同一套 SPA 响应式改造（断点 768px）

### 布局（MainLayout）
- ≥768px：现有侧边栏布局不变
- <768px：侧边栏隐藏 → 顶部栏（系统名 + 汉堡按钮 ☰ + 退出）；点汉堡从左侧滑出抽屉菜单（el-drawer size 70%，选中后自动关闭）

### 列表页（Bookings/Customers/Hotels/Holders/Golf 五页统一模式）
- **同页渲染两套列表**，CSS 媒体查询切换显示（.desktop-table 默认显示 / .mobile-cards 默认隐藏，<768px 反转）——无 JS 状态、改动小、稳定
- 移动卡片设计（每行数据一张卡）：
  - 预定：标题行=客户名+状态徽标；副行=酒店名；信息=入住~离店(晚/间)、明细摘要、卖价/利润、权益(×N/预订人)、下单时间；底部操作按钮组（详情/编辑/复制/删除，小尺寸按钮）
  - 客户：姓名+双标签徽标；微信/电话；权益列不需要；累计消费/间夜
  - 酒店：名称+政策徽标；城市地址；房型数/预定数；操作（编辑/房型/指南/删除）
  - 预订人：姓名+合作中/出权益徽标；卡片类型/来源；酒店权益+高尔夫权益摘要+更新月高亮；操作
  - 高尔夫：客户+状态；球场/日期/人数；卖价/利润；权益种类/预订人/教定位；操作
- 筛选区：桌面平铺不变；<768px 折叠为一行（关键词输入+「筛选」展开按钮），展开显示其余筛选项

### 抽屉/对话框
- <768px：el-drawer size 100%；el-dialog width 92%（CSS 全局覆盖 + :size 响应式绑定均可，选 CSS 全局覆盖最省事）
- 表单控件自动堆叠（Element Plus 默认即可），明细行（每间房）在移动端仍可增删

### 仪表盘
- 统计卡 el-col 改响应式（:xs=12 :sm=8 :lg=6 之类），移动端 2 列排列
- 最近预定表 → 移动端复用预定页卡片模式（简化版：客户/酒店/日期/金额/状态）

### 其他
- index.html 已有 viewport meta（无则补）
- 全局 CSS：媒体查询下减小页面 padding、字号微调；按钮触控区 ≥40px
- 不引入新依赖；Element Plus 组件复用

## 验收场景
1. iPhone 尺寸（375×812 模拟）逐页打开：无横向滚动、无元素溢出、控制台零错误
2. 汉堡菜单开合、跳转、自动收起
3. 五个列表页移动卡片渲染与桌面表格数据一致；操作按钮（详情/编辑/复制/删除）可点且生效
4. 新建/编辑抽屉在移动端全宽可用：酒店单（日期选择/明细增删/张数）、高尔夫单（球场/种类联动）
5. 桌面端（≥1280px 模拟）回归：布局与现在完全一致
6. 指南复制、409 提示、toast 在移动端正常
